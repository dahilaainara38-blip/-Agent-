# 手工验收测试方案

基线：2026-09 重构完成后（P0 可靠性 + P1 领域事件 + P2 前端迁移 + SSE 流式）。
适用环境：本地 `./mvnw spring-boot:run`（注意从本会话启动需 `env -u DASHSCOPE_API_KEY` 前缀）。
测试账号：注册新账号或用现有账号；建议准备 2 个账号（A 主测、B 验证归属隔离）。

通过标准：P0 项全部通过才可发布；P1/P2 允许非阻塞问题记录后跟进。

## 一、冒烟主线（5 分钟，最先跑）

| # | 操作 | 预期 |
|---|---|---|
| S1 | 打开 `/login`，登录账号 A | 进入 `/home`，问候语含用户名 |
| S2 | 首页统计卡：植物/宠物数量、待办提醒数 | 三个数字正常显示（无 `-` 或空白） |
| S3 | 进入 `/agent`，发送「北京今天天气怎么样？」 | ① 先显示"正在思考…"→"正在调用工具…" ② 回复逐字打出（打字机） ③ 右侧"执行轨迹"出现 getWeather 条目 ④ 回复完成后左栏"历史会话"出现本条 |

S3 即 SSE 流式全链路；若回复一次性整段蹦出说明走了同步端点（异常）。

## 二、Agent 工作台核心功能

### 2.1 会话管理（P2-11）

| # | 操作 | 预期 |
|---|---|---|
| C1 | 发几条消息后刷新页面（F5） | 当前会话自动恢复，历史消息完整回放（含图片消息的缩略图） |
| C2 | 点击左栏另一个历史会话再切回 | 消息流正确切换；右侧轨迹面板随之刷新 |
| C3 | 点顶栏「↻ 新会话」 | 消息区清空、会话 ID 更新、历史列表新增一条 active 高亮 |
| C4 | 历史会话列表 | 每条显示首条消息摘要（≤80 字）+ 更新时间；最多 20 条 |

### 2.2 确认卡闭环（P0/P1 重点，此前线上从未工作过）

| # | 操作 | 预期 |
|---|---|---|
| K1 | 「帮我建一个提醒：明早 8 点给咪咪喂药」 | LLM 回复后出现「确认创建护理提醒」卡片，列出参数；**卡片必须出现**（回归 off-by-one） |
| K2 | 点「确认执行」 | 卡片变"EXECUTED"，随后助手消息确认提醒已创建；首页待办数 +1 |
| K3 | 再触发一次同类请求，点「取消」 | 卡片变"CANCELLED"，不产生提醒 |
| K4 | 说「保存一条护理记录：今天喂了30克猫粮」（选中某对象） | 出「确认保存护理记录」卡 → 确认 → 右栏"护理记录"面板出现该条 |
| K5 | 快速连点「确认执行」两次 | 第二次得到"正在执行/已执行"提示，**不重复执行**（回归并发 claim） |

### 2.3 档案管理（P2-12）

| # | 操作 | 预期 |
|---|---|---|
| T1 | 左栏「＋ 新建档案」建一只宠物（名字/品种） | 表单提交后对象列表立即出现；顶栏下拉同步；右栏记录面板联动 |
| T2 | hover 对象行点「×」删除 | 确认后从列表消失；再次刷新**不再出现**（回归 CARE_TARGET 复活 bug） |
| T3 | 对话中「帮我建一个叫小绿的植物档案」 | LLM 走 createCareSubject → 确认卡 → 确认后对象列表自动刷新出现 |
| T4 | 对话中「识别结果帮我存成档案」 | 同上走确认卡（写操作永不见直接执行） |

## 三、多模态与诊断（P1-7/P2-14）

| # | 操作 | 预期 |
|---|---|---|
| M1 | 点「+」上传一张植物照片，发送「这是什么植物？」 | 回复描述植物；轨迹出现 analyzeImage |
| M2 | 上传叶片照片，发送「这叶子是不是生病了」 | 回复【病害诊断结果】结构化内容（病名/置信度/治疗方案）；**结尾提示"尚未保存，如需存历史请告诉我"** |
| M3 | 接着说「帮我保存这次诊断」 | 出「确认保存诊断记录」卡 → 确认 → 提示已存历史 |
| M4 | 新会话说「我之前的诊断记录有哪些？」 | LLM 调 listDiagnosisHistory 列出刚保存的诊断 |
| M5 | 不传图直接说「帮我诊断这盆花」 | 提示"请先上传一张照片"，**不是**"失败：null" |

## 六、边界与异常

| # | 操作 | 预期 |
|---|---|---|
| E1 | 账号 B 癝录，访问账号 A 会话的 traces/消息 | 拿不到任何 A 的内容（空列表或 400，无泄露） |
| E2 | 1 分钟内高频发消息（>30 条/分钟） | 出现"工具调用过于频繁"提示而非雪崩 |
| E3 | 断网/LLM 故障时发消息 | 收到"处理失败"提示，页面不卡死；服务端日志有根因（`Agent stream task failed`） |
| E4 | 发送过程中关闭浏览器标签页再开 | 应用日志显示 SSE 发送失败并终止任务；无残留会话状态 |
| E5 | 上传 >10MB 图片 | 被拒绝且提示明确 |

## 七、建议执行顺序

1. 冒烟主线（S1-S3）→ 2. 确认卡（K1-K5）→ 3. 档案（T1-T4）→ 4. 多模态（M1-M5）→ 5. 会话与记忆（C/K/R）→ 6. 周边页面（P）→ 7. 边界（E）

发现问题记录：现象 + 复现步骤 + `/tmp/wl_app.log` 中对应时间段的关键行。

## 附：LLM 行为说明

工具调用由 LLM 决策，存在措辞敏感性：如「给咪咪建提醒」可能被理解为先给"咪咪"建档案（调用 createCareSubject）而非建提醒。system prompt 已加入硬指令（写操作必须调对应工具、时间用 `yyyy-MM-dd HH:mm`），但测试时若未出现预期确认卡，先换更明确的措辞重试（如「为当前对象创建护理提醒：明早8点喂药」），连续不出卡才是 bug。
